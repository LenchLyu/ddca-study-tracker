# 在 Notion 中恢复进度表

可以通过 CSV 导入数据，再恢复字段与视图。完整定义见仓库根目录的 `schema.json`。该文件是可移植的设计说明，不是 Notion 原生一键导入文件。

## 一、导入与字段

将 `data/tasks.csv` 导入为“学习任务”。任务名称为标题；官方顺序与资料年份为数字；任务类型、所属阶段、学习优先级、掌握程度、验证范围、资料核对为单选；状态使用状态字段；资料与答案、视频字段使用 URL。

新增日期字段：实际开始日期、完成日期、下次复习日期。新增文字字段“待解决问题”和 URL 字段“笔记或代码链接”。日期保持空白，不把课程原始排期作为个人学习日期。

创建空白的“学习记录”表，字段见 `data/study-log.csv`。记录名称为标题，日期为日期，本次用时为数字，其余描述为文字。不要添加示例学习记录冒充真实进度。

## 二、恢复关联

1. 在“学习任务”建立指向本表的单向关联“前置任务”和“相关任务”。
2. 使用任务编号查找目标行，分别根据 CSV 的“前置任务编号”“相关任务编号”或 JSON 的 `prereq`、`related` 连接记录。新工作区中不要沿用其他人的页面 ID。
3. 在“学习记录”建立指向“学习任务”的双向关联“关联任务”，反向字段命名为“学习记录”。
4. 文本编号列只是恢复时的辅助列；保留或隐藏均可，之后用真实关联字段操作。

## 三、公式与汇总

在“学习任务”添加公式“完成值（%）”：

```text
if(prop("状态") == "已完成", 100, 0)
```

添加公式“可开始”：

```text
and(prop("状态") == "未开始", prop("前置任务").filter(current.prop("状态") != "已完成").length() == 0)
```

在“学习记录”添加公式“分摊用时（分钟）”：

```text
if(empty(prop("关联任务")), 0, prop("本次用时（分钟）") / length(prop("关联任务")))
```

添加公式“本周用时（分钟）”：

```text
if(empty(prop("日期")), 0, if(and(prop("日期") >= dateSubtract(today(), day(today()) - 1, "days"), prop("日期") < dateAdd(dateSubtract(today(), day(today()) - 1, "days"), 7, "days")), prop("本次用时（分钟）"), 0))
```

在“学习任务”添加汇总“累计学习时长（分钟）”：选择关联“学习记录”，汇总该表的“分摊用时（分钟）”，计算方式为求和。一次日志关联多个任务时，用时均分；仪表盘总用时直接对原始日志求和，避免重复计算。

## 四、视图

| 视图 | 筛选与布局 |
| --- | --- |
| 学习总览 | 主线必学；按所属阶段分组、官方顺序升序 |
| 当前学习 | 状态为学习中或待验收；按状态分组的看板 |
| 待开始 | 主线必学且未开始；显示可开始、前置任务与资料 |
| Homework | 任务类型为 Homework；题目和答案分开显示 |
| Labs | 任务类型为 Lab；按编号排序，显示验证范围与代码链接 |
| 待解决问题 | 待解决问题非空 |
| 待复习 | 复习日期非空且不晚于今天，日期升序 |
| 选学解题 | 辅助选学；按官方顺序升序 |
| 全部任务 | 全部任务，提供类型和状态筛选 |
| 依赖关系 | 主线必学且未开始，显示可开始、前置任务、相关任务 |
| 学习日志 | 学习记录按日期降序 |

公式条件不被 Agent 的视图接口支持时，显示“可开始”列供选择，不要声称已经建立自动就绪筛选。

## 五、仪表盘

按平台实际支持能力创建图表；无法自动创建时，按以下定义手动配置。

- 各类完成率：仅主线，按任务类型分组，对“完成值（%）”取平均。
- 各类任务数量与状态：仅主线，按类型分组、按状态堆叠计数。
- 各阶段完成率：仅主线，按阶段分组，对“完成值（%）”取平均。
- 本周用时：学习日志的“本周用时（分钟）”之和。
- 累计用时：学习日志的“本次用时（分钟）”之和。
- 进行中的任务：学习中与待验收的任务数。
- 有待解决问题的任务：待解决问题非空的任务数，不是问题条数。
- 已完成主线任务：主线且已完成的任务数。

## 六、日常维护

每次学完新增一条真实日志，更新关联任务的状态与掌握程度。当前未解决的问题在任务表维护，日志保留当次背景，无需重复抄写。Lab 区分仿真与上板结果，复习日期按需要填写，不预设提醒。
